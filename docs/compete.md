# Compete: the Daily Run, time trials, duels and ghosts

The contract the competitive modes share across game-core, the server and the client. Every run is replay-verified, so every run is also a ghost: its log, replayed from its start save and seed through the same driver the server used, is that run frame for frame.

## The Daily Run

- **Seed:** `dailySeed(day) = HMAC-SHA256(SEED_SECRET, "daily-seed\0" + day)`, first 32 bits. The same for everyone that UTC day, unknowable before it.
- **Hero:** `dailySave(day, look)`: the same standard hero for everyone (level 3, 112 HP, night 3 so villains at level 2, no quest, no mastery) with the day's kit (`dailyKit(day)`: three starter powers and one advanced, from a public hash of the day). `look` (the player's hero name and suit) is cosmetic: the sim never reads it, so every player plays the same city and stops (test: one player's log replays to the same hash on another's save).
- **Sim:** the patrol night, ruleset 4, unchanged. Its log carries `RULESET_VERSION`; a Daily can't be submitted against any other run because the run row pins its seed and start save.
- **Verification:** `verifyRun` exactly as a ranked night, from `runs.start_save` (the Daily save) and the day's seed.
- **Accept:** the run goes on the `daily` board for its day when it's the player's best (score desc, ticks asc). Never the save, never Bits, never Tonight, the Season or All time.
- **Attempts:** 3 a UTC day; the best counts. Abandoning a run in flight spends it.
- **Streak:** UTC days in a row with a verified Daily, up to today (or yesterday until today's is run).
- **Badges:** once a day's last run could no longer be submitted (midnight + 45 min + 2 min), `settleDailies` queues `daily-podium` to its top three and `daily-winner` to first through `mint_rewards`' `badges` (as case-001's badge), with the player's next reward nonce. It runs from `after()` when the hub or a Daily board is read, at most every 10 minutes (`background.ts` window `dailies`), never a cron. Idempotent.

## Time trials (`trial-1`)

- **Courses:** each its own fixed city (`COURSE_GEOMETRY`: a patrol city from the course's seed and a stop list that shapes districts, the river and the bridge, then no zones) with hand-laid gates: roofs, street canyons, Doc's deck, a climb.
- **Sim:** gated on `SimConfig.trial`; patrol and chapter states have no `trial` field and hash as before. The gates are the night's boost rings (`state.pickups`), taken one at a time in order within the ring's reach, each with the ring's boost. Through the last one the clock stops (`trial-finish`, then `night-over`). Out of time at 240 s, unfinished. The hero has no powers and no Gwei: movement only. `stopTarget` is the next gate, so webs aim at it.
- **Medals:** from the course designer's practice: the trial bot raced each course in 243 styles. `dev` is the fastest (the verified golden log), `gold` beats nine practice runs in ten (10th percentile), `silver` three in four (25th), `bronze` half of them (the median), each rounded up to a tenth of a second (`MEDAL_TICKS`, written by the golden regeneration).

- **Verification:** `verifyTrialRun`: `replayRun(input, { trial: course })` from the trial save, the same plausibility rules with a 3 s floor. A finish goes on the `trial` board for its course (`best_score` = medal tier 0–4, `ticks` = time).
- **Goldens:** `test/golden/trial-<course>.{bin,json}`, `src/golden-trial.ts`; regenerate with `UPDATE_TRIAL_GOLDEN=1 pnpm --filter @wgp/game-core test trial-golden` (and bump `TRIAL_RULESET`).
- **Refusals** (tests): a trial log isn't a patrol night, a case or another course; a patrol or case log isn't a trial; a run can't be both.

## Duels

`{ duel: runId }` on a verified run: today's Daily opens the Daily with that ghost; a course opens the course with it; a ranked night (or an earlier Daily, or another duel) is raced again on its own seed and start save (`duelSave`: the ghost's save, named and dressed as the challenger), verified as a patrol night, unranked: on no board. The results say who won (`compareRuns`: a trial by finish then time, a patrol by score then time; a dead heat isn't a win).

## Ghosts (`@wgp/game-core/ghost`)

- `buildGhost(input, opts)` replays a log through `stepRun` and keeps, per tick, the hero's position, facing, action and web anchor, its splits (`arrive` or `trial-gate` ticks), checkpoints and final hash. The client keeps a ghost only if those equal the server's stored ones.
- `raceProgress(state)` rises through a run (stops reached, the way to the next, a fight's hits; a trial's gates); `ProgressMeter` keeps the live run's running best and when it was set; `ghostGap` is how much later you reached it than the ghost did (and grows while you stall where the ghost didn't).
- Drawn at the player's own tick (`view.tick − 1 + alpha`): one instanced draw for every ghost (a translucent paper outline of the hero cut-out, facing the camera about its up, hanging toward its anchor on a web) and one for the webs. No depth writes, no glow.

## Server API

- `POST /api/runs/start` takes `{ mode: "daily", ghost? }`, `{ mode: "trial", course, ghost? }` or `{ duel: runId }` (with `abandon?`). Answers the usual fields plus `compete: { kind, course, ghost, startSave }`: play with `startRun(startSave, seed)` (Daily, duel) or `startTrialRun(startSave, course)`. 409 `run_active`, 429 `daily_cap`, 400 `no_course` / `not_raceable`, 404 for an unknown ghost. Races have their own burst guard (24 a minute).
- `POST /api/runs/:id/submit` replays by mode and answers `ranked: false, bits: 0` plus `compete: { kind, course, score, ticks, finished, medal, improved, best, rank, total, ghost, won, streak? }`. Idempotent like a ranked night.
- `GET /api/compete`: the hub (`CompeteView`): today's Daily (day, reset, kit, seed, attempts, best, rank, streak, podiums, badges, top five), each course (your best and medal, the record), your rivals, races left, a run in flight.
- `GET /api/compete/ghosts?mode=daily|trial&course=&ghost=`: the runs to race (the board's top three, your best, a chosen run). Each one's replay is `GET /api/runs/:id/replay` (now with `mode` and `course`).
- `GET /api/compete/race/:runId`: what a challenge link opens (`opens: "daily" | "trial" | "duel"`).
- `GET /api/leaderboard?board=daily[&period=YYYY-MM-DD]` and `?board=trial:<course>`: the LeaderboardView shape. Tonight, Season and All time are untouched.
- `GET /api/me`: `activeRun` adds `mode` and `course`.

## Client

- `/play/compete`: the hub (dock tab "Compete", which also stays lit on `/play/leaderboard`; Tonight has a Compete tile).
- `/play/compete/daily[?ghost=]`, `/play/compete/trial/<course>[?ghost=]`, `/play/compete/duel/<runId>`: full-screen races on the patrol's PlaySurface through its `addon` (ghosts in the scene, the gap chip, splits, ghost name tags, a trial's gate pin and clock), with their own recording slot (`race:daily:<day>`, `race:trial:<course>`, `race:duel:<runId>`) so a race never overwrites tonight's patrol recording. A reload during a signed-in Daily resumes it.
- `/play/compete/race/<runId>`: a challenge link; it redirects to the right race. Shared from the results (a race's or a ranked night's: "Copy challenge link"), and offered on `/r/<runId>` ("Race <handle>'s ghost"), which now also shows Daily Runs.
- Guests race everything on their device (the Daily on the day's public seed), unfiled; a trial's best is kept in this browser.
